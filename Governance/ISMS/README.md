> Simulated ISO/IEC 27001:2022 case study. Documentation baseline: 2026-10-14; register updated 2026-11-10. Drafts have no management approval; the company and infrastructure do not operate. The repository's plan-analysis gate does operate. Records of things actually done are in [`records/real/`](../records/real/README.md); tabletop walk-throughs are in [`records/simulated/`](../records/simulated/INDEX.md) ([ADR-0006](../ADR/0006-simulated-operating-records.md)).

## 1. How to use this register

This is the document register for clause 7.5. Its **109 topic rows** comprise **53 Draft**, **46 Covered elsewhere**, **8 Simulated operation** and **2 Planned**. Several topics deliberately share one file; row counts are not file counts. Of the eight event records that were Planned on 2026-10-14, six now point at a simulated walk-through and one was split; the penetration test report and logging evidence stay Planned because no record of any kind exists. A simulated row is still a record of an event that has not happened.

- **Draft**: substantive file exists; no approval is implied. A log may be empty by design and a template is not a completed record.
- **Covered elsewhere**: the linked source owns the topic; its own status and limits apply.
- **Simulated operation**: the event record is a bannered tabletop walk-through under [`records/simulated/`](../records/simulated/README.md), as defined in [ADR-0006](../ADR/0006-simulated-operating-records.md). No such event took place. The row still needs the real activity.
- **Planned**: no event record exists, real or simulated. These rows require real activity, not more prose.

Owners below are accountable roles in the simulated design, not signed appointments. Unless a dated review is explicitly recorded, the review column is a proposed trigger, not an overdue claim about an approved policy. Linked documents carry document ID, version and approval conditions. The existing risk register is an exception: its scheduled review is overdue and remains visible. [Document control](00-context-and-governance/document-control-procedure.md) governs approval, revision, access, supersession and ISMS change planning.

Document status is separate from control status. The [SoA](04-controls-and-soa/statement-of-applicability.md) covers all 93 Annex A controls using Implemented / Partial / Simulated operation / Gated design / Designed / Planned, with a scope-specific evidence boundary. No amount of draft documentation establishes operating effectiveness or certification.

## 3. What remains before operation or assurance

**Simulated records and the "do not backdate" rule.** The 2026-10-14 baseline said: do not reconstruct minutes, do not backdate measurements. That rule stands. [ADR-0006](../ADR/0006-simulated-operating-records.md) does not relax it; it adds a separate store. A simulated record is not filed among real records, carries the banner `SIMULATED RECORD` under its title, and states two dates that are never merged: `Authored` (2026-11-10, the real day the file was written) and `Scenario date` (the day inside the fiction). A scenario date of 2026-04-08 on SIM-MON-001 is therefore not a claim that anything was measured on that day. Real logs in this folder (the [audit findings log](09-internal-audit/audit-findings-log.md), the [management review action log](10-management-review/management-review-action-log.md), the [nonconformity log](11-improvement/nonconformity-and-corrective-action-log.md)) stay empty of fictional entries; their ID schemes are reserved for real events.
