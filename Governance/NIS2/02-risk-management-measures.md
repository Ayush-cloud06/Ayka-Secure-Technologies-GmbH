## 1. Why this exists when NIS2 does not apply

Ayka is out of scope ([NIS2-01](01-applicability-assessment.md)). This assessment still matters for two reasons:

1. **Customers ask for it.** In-scope customers must judge the security practices of their suppliers. They will ask the questions in this table, in this order, because it is the order of NIS2 Art. 21(2) and §30(2) BSIG.
2. **There is no transition period.** Once Ayka qualifies (50 AWU or the financial thresholds in two consecutive financial years, see NIS2-01 section 4), these measures are a legal duty from that day. Everything below that is still "Planned" on that day is a breach.

The yardstick is the BSIG list, not ISO 27001. ISO 27001 controls are given for cross-reference because the [ISMS](../ISMS/README.md) is the management system Ayka will use to run these measures. For cloud computing service providers, the detailed content of each measure is set by the annex of Implementing Regulation (EU) 2024/2690, which is more specific than §30 BSIG; section 4 covers what it adds.

## 2. How status is judged

The labels follow the repository's capability yardstick ([README, section 4](../../README.md#4-capability-status)). The weakest true label wins.

- **Implemented**: runs today and something shows it working (a CI run, a test, a configured setting).
- **Partial**: some of the measure is implemented; the gap is named.
- **Simulated operation**: a design exists and a bannered tabletop record walks it end to end ([ADR-0006](../ADR/0006-simulated-operating-records.md)). It is not operating evidence. A row with this label links a record under `records/simulated/`. Where the record belongs to another document set, the row says "+ simulated record SIM-xxx" next to a weaker label instead.
- **Gated design**: Terraform exists, the CI gate checks its plan, and it has never been applied.
- **Designed**: a document or ungated Terraform exists but has never been applied or exercised.
- **Planned**: only written down as an intention, or not at all.

Order of strength: Planned < Designed < Gated design < Simulated operation < Partial < Implemented.

Remember what the repository is: the compliance gate runs for real on every pull request, but no infrastructure is deployed. A measure that depends on a running AWS account can at best be "Designed".

## 4. What Implementing Regulation 2024/2690 adds for a cloud provider

If Ayka comes into scope as a cloud computing service provider, the annex of the implementing regulation defines the measures in 13 sections. Most map onto the table above. Points that go beyond it and are easy to miss:

| Annex section | Requirement beyond §30(2) BSIG | Ayka position |
|---|---|---|
| 1 Policy on the security of network and information systems | Policy approved by management bodies, reviewed at least annually, with named roles reporting to management | Policy exists as a draft; annual review and approval not yet done (a management review is walked through in [SIM-MR-001](../records/simulated/management-review/SIM-MR-001-management-review-2026.md)) |
| 2 Risk management | Compliance monitoring and a regular independent review of network and information security | No real internal or external audit; one internal audit walked through ([SIM-AUD-001](../records/simulated/audit/SIM-AUD-001-internal-audit-plan-2026.md)) |
| 3 Incident handling | Logging of a defined set of events, monitoring, and retention of logs for a documented period | Retention is documented in the [logging and monitoring standard](../policies/logging-and-monitoring-standard.md) (STD-LOG-01, draft): CloudTrail one year online then archive six years (Designed); flow, WAF, application and access logs 365 days (Gated design); database logs 90 days, Entra ID and GitHub exports one year (Planned). The standard is not approved and no log source runs |
| 4 Business continuity | Backup copies kept separate from the production environment; regular restore tests | A locked backup vault is Gated design (never applied) but sits in the same account as the workload, so it does not yet meet "separate from the production environment"; restore test: a tabletop ([SIM-BCP-001](../records/simulated/continuity/SIM-BCP-001-restore-and-dr-tabletop.md)) and one local-container run of the method ([REAL-INFRA-002](../records/real/infra/REAL-INFRA-002-restore-test-local-postgres.md)) |
